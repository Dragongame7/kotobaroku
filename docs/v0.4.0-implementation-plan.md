# ことば録：v0.4.0実装方針書

- 作成日：2026-10-17（日本時間）
- 対象：`nemotron-web`。`0.3.0` を基に `0.4.0` を実装。
- 文書の状態：コード実装・Ollamaとモックでの検証を実施。外部vLLMの実接続は接続先未定のため未検証。結果は11章。
- 利用者からの要望：LLM接続設定を別にまとめて設定項目を追加する。ライブ翻訳を全画面表示できるようにし、広く感じる文字間隔を改善する。
- 前版：[v0.3.0実装方針書・実装結果](v0.3.0-implementation-plan.md)。本書に記載のない認識・補正・翻訳・保存の仕様は現行実装を引き継ぐ。

## 1. 今回の方針

1. **「LLM接続設定」を独立した設定画面へまとめる。** 通常画面やライブ画面の操作欄へ接続先の技術設定を増やさない。
2. **現在のOllama接続を維持し、外部vLLMへURLで接続できるようにする。** 接続方式、ベースURL、モデル、必要に応じたAPIキーを設定する。
3. 補正・文末判定・翻訳・整形・要約は、アプリ共通で一つの接続先・モデルを使う。既存の用途別処理や翻訳キューは共有する。
4. **ライブ翻訳に「全画面表示」を追加する。** 開始前・録音中・残処理中・再試行中でも表示を切り替えられ、録音や翻訳は継続する。
5. **原文・訳文の文字間隔を自然にし、行間と余白も整理する。** 日本語、英語、日英混在で読みやすさを確認する。本文の空白文字や保存内容は書き換えない。
6. 最新順の対訳、同一区間の更新、履歴閲覧中の位置保持、時系列順のコピー・保存を引き継ぐ。

独立した設定画面のURLを `/#settings` とする。既存の `/#live`、`/#translate`、`/#compare` と通常の文字起こしの入口は維持する。

## 2. 現状と変更が必要な理由

### 2.1 LLM接続

`server/config.mjs` は既定で `http://127.0.0.1:11434` のOllamaと `gemma4:latest` を使う。`OLLAMA_URL` / `OLLAMA_HOST` による接続先変更と、`OLLAMA_MODEL` によるモデル指定は既に可能である。Gemmaはアプリ内蔵ではなく、別サービスへのHTTP接続で利用している。

ただし、生成・補正・文末判定・接続確認・モデル管理はOllama固有のAPIと応答形式に依存している。vLLMのURLを既存の `OLLAMA_URL` に入れるだけでは対応できない。UI側にも `health.ollama`、Gemma固定の案内、常時「ローカルで処理」とする表示がある。

今回の変更では接続先の設定とAPIの差を共通処理へ集約し、各機能にvLLM用の翻訳処理を複製しない。

### 2.2 ライブ翻訳の表示

現在はアプリのヘッダー、ページ見出し、作業タブの下にライブ画面があり、会話欄の高さは `clamp(280px, 51vh, 620px)` である。大きな画面でも、会話に使える領域には上限がある。

現在のライブ本文には、字間を広げる `letter-spacing` の明示指定はない。一方で行高は `1.95`、本文の左右余白は26px、最新行の最小高は210pxである。見出しやブランドの一部には別途字間指定がある。

「文字間が広い」という見え方の原因を、行間だけと決めつけない。実装開始時に適用フォント、フォントの代替、計算後の字間・単語間隔、折り返し、ブラウザ倍率を確認し、水平の文字間隔と垂直の読みやすさを分けて調整する。

## 3. 独立したLLM接続設定

### 3.1 入口と設定の分離

- 共通ヘッダーに「設定」の入口を置く。通常画面のサイドバーとライブ画面からも同じ設定画面へ移動できる。
- 設定画面の最初の項目を「LLM接続」とする。今後の設定項目を追加できる構成にするが、今回は空のカテゴリを増やさない。
- マイク、話す言語、訳すタイミング、日本語補正ON/OFFは、現在の作業に近い場所に残す。接続方式・URL・APIキーをライブ画面の折りたたみ設定へ混在させない。
- 現在のモデル表示は接続状態の要約にし、モデルの変更操作は設定画面へ集約する。
- 「戻る」で直前の作業画面へ戻れるようにする。`/#settings` を直接開いた場合の戻り先はライブ翻訳とする。
- 設定画面を開いても、会話・原稿・履歴・比較結果を消さない。共通の翻訳コントローラを再作成しない。

### 3.2 設定項目

| 項目 | 方針 |
|---|---|
| 接続方式 | `Ollama` / `OpenAI互換（vLLM）` の二つ |
| 接続先URL | Ollamaは例 `http://127.0.0.1:11434`、vLLMは例 `http://192.168.1.100:8000/v1`。例のアドレスへ自動接続しない |
| モデル | 接続先が公開するモデルID。取得候補から選べ、手入力もできる |
| APIキー | 認証が必要な場合に入力。未設定・保存済み・変更・削除を区別する |
| モデル一覧を取得 | 入力中の接続先から取得する。取得失敗だけを理由に手入力を禁止しない |
| 接続をテスト | 通常生成、差分受信、JSON形式の応答を確認する。実際の会話ではなく固定の短い確認文を送る |
| 保存して適用 | テストに成功した設定を保存し、次の処理から適用する |
| 現在の設定・状態 | 適用中の方式、URL、モデル、設定の由来、最終確認時刻を表示する。キーは表示しない |

ベースURLはAPIの起点であり、`/chat/completions` などの個別エンドポイントを入力する欄にはしない。末尾のスラッシュを正規化し、リバースプロキシのパス接頭辞は維持する。HTTP/HTTPS以外、ユーザー名・パスワード入りURL、クエリ・フラグメント入りURLは入力エラーとして扱う。

モデル一覧取得が利用できなくても、指定モデルで生成・差分受信・JSON出力を確認できれば適用できる。一覧の取得成功だけでは利用可能と判定しない。既知の「モデルが存在しない」「認証に失敗」「JSON形式に未対応」「応答が途中で終了」を区別して案内する。

### 3.3 編集・テスト・適用の状態

入力中の設定と適用中の設定を分ける。URLの入力やモデル一覧取得だけでは現在の接続先を変更しない。

1. 設定を編集する。
2. 入力中の設定に対して接続テストを行う。テスト中は中止できる。
3. 通常生成・差分受信・JSON出力の結果を表示する。必要条件に失敗した場合は現設定を維持する。
4. テスト成功後に「保存して適用」を押す。テスト後にURL・モデル・認証を変更した場合は結果を無効にし、再テストを必要とする。
5. 保存成功時だけ適用中の設定を置き換え、接続状態を再取得する。保存失敗時は現設定を維持し、再起動後と稼働中で接続先が食い違わないようにする。

準備中・録音中・残処理中・再試行中・比較中・整形／要約中は、接続設定の変更とテストを行わない。UIの無効化に加えサーバーでも既存の排他を使って拒否する。接続テストもLLMを使用する処理として排他に含める。

一つの処理は開始時の接続設定のスナップショットを使い続ける。テスト済み設定の識別と保存・適用はサーバーで検証し、複数タブからの操作でも途中の会話に別の接続先が混在しないようにする。

### 3.4 保存・旧設定の引き継ぎ

- 接続設定の所有者はサーバーとし、非公開のローカルファイル（案：`.local/llm-settings.json`）へ保存する。`dist` 配下やブラウザの `localStorage` には保存しない。
- 適用設定の優先順位は、**画面から保存した設定 → 新しい環境変数の設定 → 既存のOllama環境変数 → 既定値**とする。設定は方式・URL・モデルを一組で選び、別の方式の設定を項目単位で混ぜない。
- 新しい環境変数の名前は `LLM_PROVIDER`、`LLM_BASE_URL`、`LLM_MODEL`、`LLM_API_KEY` を候補とする。環境変数で新方式を指定する場合の必須組み合わせを定め、不完全な指定は設定エラーとして案内する。環境変数は保存設定がない場合の初期値として使用することを文書化する。
- 既存の `OLLAMA_URL` / `OLLAMA_HOST` / `OLLAMA_MODEL` はOllama設定として引き継ぐ。新しい設定がなければ、現行のローカルGemmaでそのまま起動する。
- 破損した保存ファイルは黙って初期化しない。会話を保持したうえで設定の読み込みエラーと修正方法を表示する。
- APIキーはサーバー専用の保存領域に保持し、画面への取得応答、ヘルス応答、ログ、会話の保存・コピーへ含めない。ファイルへ保存する場合は平文保存であることを設定の説明に明記し、OSのアクセス権を制限する。暗号化された資格情報保管庫の追加は今回の対象外とする。
- 保存ファイルとキーはGit管理対象外にする。保存は一時ファイルからの置換などで行い、中断で不完全なJSONを残さない。
- キーの未変更・置換・削除はAPI上も区別する。方式またはURLが変わったときは、前の接続先のキーを自動流用せず再入力を必要とする。

## 4. OllamaとvLLMで処理を共用する構成

### 4.1 共通クライアント

ブラウザは引き続きことば録のバックエンドへ接続する。vLLMへブラウザから直接接続せず、APIキーの扱い、ストリーム変換、中断、エラー処理をサーバー側で共通化する。

```text
文字起こしの補正 / 文末判定 / 翻訳 / 整形 / 要約
                      ↓
           共通LLMクライアント
                      ↓
           Ollama / OpenAI互換（vLLM）
```

| 機能 | Ollama | OpenAI互換（vLLM） |
|---|---|---|
| モデル候補 | `/api/tags` | ベースURL配下の `/models` |
| 文章生成 | `/api/chat` | ベースURL配下の `/chat/completions` |
| 差分受信 | NDJSONを解析 | SSEを解析し、共通の本文差分へ変換 |
| JSON形式の応答 | `format` | JSON Schemaの指定へ変換し、採用するvLLMで確認 |
| 認証 | 設定した場合のみ接続先の対応に合わせて送信 | 設定したAPIキーをBearer認証で送信 |
| 起動準備 | 現行のOllama向け準備を維持 | 生成可能か確認。Ollama向けの空メッセージ要求は送らない |
| モデルの起動・解放 | 既存のOllama向け処理 | アプリから操作しない |
| GPU配置の確認 | 取得できたOllama情報を表示 | 未取得・対象外として扱い、GPU常駐を推測しない |

vLLMがOpenAI互換のChat APIを提供することは[公式のAPI資料](https://docs.vllm.ai/en/latest/serving/online_serving/openai_compatible_server/)を参照する。JSON出力の指定は[Structured Outputsの資料](https://docs.vllm.ai/en/latest/features/structured_outputs/)に従い、採用バージョンと実際の接続先で確認する。

`keep_alive`、`num_ctx`、`num_predict`、`think` などのOllama固有項目をvLLMへそのまま送らない。出力上限、温度、JSON Schemaなどを共通の要求として扱い、接続方式に合わせて変換する。推論過程など本文以外のフィールドを訳文へ混ぜない。モデル固有のチャット形式は対応を確認する。

SSEはネットワークの一回の受信と一イベントが一致すると仮定しない。分割されたUTF-8、複数行、終了通知、本文のないイベント、途中切断、キャンセルを処理する。生成途中の切断を完了扱いにせず、受信済み本文を保持する。別の接続先への自動切替や、同じ生成要求の無条件な再送は行わない。

### 4.2 適用範囲と既存機能

- 翻訳だけでなく、日本語補正、文末判定、通常文字起こしの補正、整形、要約も共通クライアントへ移す。
- JSONが返っても補正候補・境界位置の検証は既存どおり行う。外部モデルの回答を無検証で原文へ適用しない。
- 区切りモード、文脈の上限、翻訳キューの順番、各処理と残処理の待機上限は原則維持する。外部接続の都合だけで既定値を延ばさず、必要な調整は実装結果に記録する。
- vLLM選択時は起動スクリプトからOllamaを自動起動しない。外部サーバーの起動・モデル配置・ダウンロードは利用者が管理する。
- 明示的なモデル比較はOllama接続時の既存機能を維持する。vLLM接続時の複数モデル比較は今回追加せず、未対応であることを詳細画面に示す。
- ヘルス情報は `llm` を共通の状態とし、準備可否を `health.ollama` のみに依存させない。既存の応答項目を移行用に残す場合も、vLLM接続を「Ollama接続済み」と表示しない。
- LLMに接続できなくても、音声認識だけで利用できる操作は維持する。補正が必要な処理の失敗時は既存の原文保持・フォールバック方針を守る。

### 4.3 接続先と会話データの表示

ローカルのOllamaと外部サーバーを区別し、外部接続時に「すべてローカルで処理」と表示しない。設定画面には「文章処理は設定した接続先で実行します」と案内する。ループバック接続でも背後の処理場所を確認できない方式は、単に「このPCへ接続」と表記する。

音声認識の接続先は今回変更しない。外部LLMへは原文と処理に必要な文脈を送り、新しく音声を送る処理は追加しない。URLやAPIキーを会話へ保存する必要はない。必要な処理記録として接続方式・モデル・設定の世代を保持し、旧データに項目がなくても復元できるようにする。

## 5. ライブ翻訳の全画面表示

### 5.1 表示と操作

ライブ画面に「全画面表示」ボタンを追加する。[Fullscreen API](https://developer.mozilla.org/en-US/docs/Web/API/Fullscreen_API)を利用し、利用者がボタンを押したときにライブ画面の同じ要素を全画面化する。

```text
日本語 → 英語   [翻訳を終了]   文字サイズ [標準]   [全画面を終了]
● 聞き取り中 · そのまま話してください
──────────────────────────────────────────────────────
話したこと · 日本語                  翻訳 · 英語
最新の原文                          対応する訳文
ひとつ前の原文                      対応する訳文
                 会話に残りの高さを使う
──────────────────────────────────────────────────────
↑ 新しい会話 / ↓ 過去の会話       [新しい会話 ○件 · 最新へ戻る]
```

- 全画面では共通ブランド、ページ見出し、作業タブ、通常画面のフッターを表示せず、会話の領域を優先する。
- 方向と主操作、マイクの状態、文字サイズ、列見出し、最新へ戻る、全画面の終了は利用できる状態にする。方向と翻訳設定の処理中ロックは維持する。
- 会話欄は全画面の残りの高さを使い、通常時の620px上限を外す。操作部分と会話部分を分け、スクロール対象は会話欄を基本とする。
- 幅が狭い場合は従来どおり原文・訳文を同じペアの上下に置く。低い画面や文字拡大で操作部が増えても、終了操作へ到達できるようにする。
- 設定の詳細や停止後の保存操作は必要時に開ける補助領域へまとめる。設定画面への移動は通常表示へ戻してから行い、処理中の画面切替は禁止したままにする。

### 5.2 録音や会話との関係

全画面への出入りは表示だけの操作であり、録音・WebSocket・翻訳コントローラを作り直さない。全画面を解除しても「翻訳を終了」は実行しない。反対に翻訳を終了しても、利用者が解除するまで全画面表示は保つ。

「全画面を終了」とブラウザのEsc操作に対応する。`fullscreenchange` を基準に実際の表示状態を反映し、Esc、外部要因による解除、要求失敗でもボタンの表記を合わせる。解除後のキーボードフォーカスは、元の全画面ボタンなど適切な位置へ戻す。全画面状態を永続化して、次回起動時に自動要求することはしない。

先頭追従中は切替後も最新を表示する。履歴閲覧中は基準行と会話欄内の位置、新規件数を引き継ぐ。画面が大きくなってスクロール範囲が足りなくなる場合は最も近い有効位置へ補正し、履歴閲覧中に無条件で先頭へ戻さない。

### 5.3 非対応・要求失敗

Fullscreen APIを利用できない場合やブラウザに拒否された場合は、ウィンドウ内でライブ画面をいっぱいに広げる表示を提供する。この場合は「画面を広げる」／「元の表示に戻る」と表記し、ブラウザの枠まで消えると案内しない。

全画面とウィンドウ内拡大は同じレイアウトを共有する。要求失敗を録音エラーとして扱わず、会話や処理を維持したまま表示の切替だけを案内する。

## 6. 文字間隔・行間・余白の改善

### 6.1 文字組みの初期案

| 項目 | 初期案 |
|---|---|
| 本文の字間 | `letter-spacing: normal` を明示し、広げる指定を継承しない。初期値で負の字間を使わない |
| 英語の単語間隔 | `word-spacing: normal`。単語間の空白を削除・圧縮する処理は加えない |
| 揃え方 | 左揃えを維持し、均等割り付けを使わない |
| フォント | 現行フォントで実表示を比較し、和文・欧文の代替フォントによる差を確認する。変更する場合は対象と理由を記録する |
| 本文の行高 | 現在の1.95から、原文・訳文とも1.65を初期案として比較する |
| 文字サイズ | 既存の「標準」「大きく」を維持。訳文を原文より少し大きくする関係も維持 |
| 本文の余白 | PCは上下18〜22px・左右20〜24px、狭い画面は16〜20pxを初期案とする |
| 最新行の高さ | 数行分の余裕を保ちつつ、全画面で過大な空白を占めない値に調整する。長文は自然に伸びる |

数値は実装開始時の比較案であり、実機で読みにくければ調整する。文字間の改善は行高の変更だけで完了とせず、同じ文・同じ文字サイズ・同じ幅で変更前後を確認する。

### 6.2 確認する文章と不変条件

日本語の長文、英語の文、`AIモデル API v0.4.0` などの日英混在、数字・時刻、句読点・括弧、明示改行、改行のない長い英単語を確認する。通常表示と全画面の両方で、標準・大きく・200%相当の文字拡大を確認する。

認識原文・訳文そのもの、意味のある空白、改行、コピー・保存内容はCSS調整で変更しない。文字が重なる負の間隔、行数による本文省略、固定高での切り捨てを使わない。字間や行間の変更後も、履歴閲覧中の表示位置を補正する。

## 7. 今回の対象外

用途別の異なるLLM接続先、接続プロファイルの複数保存と自動切替、外部への自動フェイルオーバー、vLLMサーバーのインストール・起動・モデル配備、vLLMでの複数モデル比較、GPU管理、音声認識先の設定変更、クラウド公開は含めない。
