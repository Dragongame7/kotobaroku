# ことば録 v1.0.0

マイク音声をNemotronで文字起こしし、設定した共通LLMで日本語補正、日英翻訳、文章整形、要約を行うWebアプリです。v1.0ではNemotron-3-Diarizationによる話者分離、話者名の変更、話者付きの翻訳・会議履歴を追加しました。

標準構成は**DGX SparkでASR・話者分離・vLLM、Windows端末で録音・表示・保存**です。GPUなしの端末も利用でき、ゲートウェイが端末間の同時1会議を制御します。[Spark配備手順](deploy/spark/README.md)、[v1.0実装方針](docs/v1.0.0-implementation-plan.md)、[技術設計](docs/v1.0.0-technical-design.md)を参照してください。

既存のローカルASR・Ollama構成も利用できます。未設定では従来のローカル接続・話者分離OFFを維持します。Spark実機の接続先は未定で、GPU同居性能・3〜8人の話者精度・60分運転は未検証です。プロトコル・排他・保存はモックと結合試験で検証しています。


## 起動

このPCではASRとOllamaを導入済みです。このディレクトリで次を実行し、[アプリ](http://127.0.0.1:3210/)を開きます。

```powershell
.\start.ps1
# またはビルド済みなら
npm start
```

終了は起動したターミナルで `Ctrl+C`。起動スクリプトが開始したサービスを終了し、すでに起動していたサービスはそのまま使います。モデルは起動時に自動取得しません。

## LLM接続設定

ヘッダーの「設定」から [LLM接続設定](http://127.0.0.1:3210/#settings) を開きます。ライブ画面の「マイクと翻訳の設定」と通常画面のサイドバーからも開けます。補正・文末判定・翻訳・整形・要約で一つの接続先とモデルを共有します。

1. 接続方式を `Ollama` または `OpenAI互換（vLLM）` から選びます。
2. 接続先URLと、接続先が公開するモデル名を入力します。「モデル一覧を取得」も利用できます。一覧を取得できない場合はモデル名を手入力できます。
3. 認証が必要な場合は「APIキー」で「新しいキーを入力」を選びます。認証のない接続先ではキーなしを選びます。
4. 「接続をテスト」で文章生成・差分受信・JSON出力を確認します。固定の確認文を送るだけで、実際の会話や接続先の変更は行いません。
5. 「保存して適用」で保存します。テスト後にURL・モデル・認証を変えた場合は、再テストが必要です。設定は次の処理から使われます。

vLLMのURLは `http://{IPアドレス}:8001/v1` の形式で指定します。`{IPアドレス}` は実際のIPアドレスに置き換えてください。`/chat/completions` は付けません。vLLM側にはChat APIとJSON Schema出力に対応するモデル・設定が必要です。Sparkでは共通ゲートウェイ経由で接続します。配備用スクリプト・Compose・サービス定義は`deploy/spark/`にあります。Thinking無効化オプションは対応モデルでのみ指定し、テストでJSON応答を確認してください。

設定はサーバーの `.local/llm-settings.json` に保存します。優先順位は **画面から保存した設定 → 新しいLLM環境変数 → 従来のOllama環境変数 → 既定のローカルGemma** です。環境変数は保存設定がない場合の初期値です。新しい方式を環境変数で指定する場合は、`LLM_PROVIDER`（`ollama` / `openai`）、`LLM_BASE_URL`、`LLM_MODEL` を一組で指定します。`LLM_API_KEY` は任意です。

APIキーはブラウザへ永続保存せず、取得APIや会話出力には含めません。サーバー側の設定ファイルには平文で保存し、OSのアクセス権で制限します。このファイルとキーはGit管理対象外です。方式やURLを変えるときは旧キーを流用せず、入力し直すかキーなしを選びます。

録音・翻訳・残処理・再試行・比較・整形・要約の途中は接続設定を変更できません。接続テスト自体も排他対象です。取得・保存エラーでは適用中の設定を維持します。壊れた保存ファイルを黙って初期化することはありません。

音声認識は既存の接続先で行い、原文と必要な文脈をLLMへ送ります。接続先に応じて「このPCへ接続」／「外部サーバーへ接続」と表示します。vLLM接続ではOllamaを自動起動せず、モデルの起動・解放・GPU配置を操作しません。モデル比較の新規実行はOllama接続時のみ対応します。

## 音声接続・話者分離・会議履歴

設定画面の「音声認識・話者分離」で、ローカルまたはDGX Spark、音声API起点、APIキー、話者分離、マイク処理を指定します。動作確認した内容だけを適用できます。Sparkでは先に音声設定を適用し、次に同じゲートウェイの`/v1`をLLMへ設定してください。詳しい入力例は[Spark配備手順](deploy/spark/README.md)にあります。

- 話者分離ONでは同じ話者の単語をまとめ、話者交代で文を区切ります。話者・音声時刻を通常画面とライブ翻訳へ表示します。原文と単語列の対応が不確かな場合は原文を保持し、「話者不明」とします。
- 話者名をクリックして変更できます。同じ録音内の表示・書き出しへ反映し、別の録音には引き継ぎません。話者番号は推定です。氏名の自動認識や重なった二人分の全文認識は扱いません。
- 会議用マイクのプリセットはブラウザの自動ゲイン・ノイズ抑制・エコー除去をOFFにします。マイク側の処理と実際の会議室で評価してください。
- 設定画面の「会議履歴」から保存結果を開き、話者名の変更、テキスト・JSON出力ができます。会議の確定原文・話者・補正・翻訳は端末Nodeの`.local/sessions/`へ逐次保存します。録音音声は保存しません。
- 切断後は未完了・欠損を示し、再開時は新しい会議IDになります。音声がないため未認識部分を再解析することはできません。接続先・話者分離の変更は録音や残処理の終了後に行います。

## 通常の文字起こしと日本語補正

1. 日本語とマイクを選び、「日本語の文脈補正」をONにして録音します。
2. 認識原文はすぐに表示します。文のまとまりごとに設定したLLMで同音異義語を検討し、補正結果と差分を別に表示します。録音中は最新部分へスクロールします。
3. 停止するとマイクを解放し、残った確定原文と補正を処理します。残処理は中断できます。
4. 原文と補正後のどちらを使うか選んで、文章整形・要約を実行できます。停止後の補正再試行、コピー、Markdown保存、履歴からの復元にも対応しています。

「天気がいいので選択しようと思います。」は「洗濯」への補正対象です。「候補から会場を選択しようと思います。」は維持します。LLMの提案は、そのまま採用せず、標準辞書の読みが一致する既知の漢字名詞への置換だけをサーバーで検証します。数字、否定、助詞、句読点、固有名詞と判断された語、引用された語は変更候補にしません。最大3か所、原文の25%か12文字の小さい方までに制限します。

曖昧な表記や意味の近い語の使い分けは見送ります。辞書で固有名詞として認識できない名前など、保護は完全ではありません。補正は取りこぼしを許容した保守的な処理です。単語登録・ユーザー辞書はありません。

補正は日本語指定時のみ有効です。OFF、英語、自動言語判定では日本語補正を要求しません。原文は上書きせず、補正に失敗・時間切れとなった区間は原文を使います。手入力で原文を編集した場合、以前の補正は古い結果として扱い、再補正するまで適用しません。録音時の原文も保存します。

## ライブ翻訳

[ライブ翻訳](http://127.0.0.1:3210/#live)では、話す言語と訳す言語を選び「翻訳を開始」を押すだけで使えます。初回はマイクの使用を許可してください。「全画面表示」で会話を画面いっぱいに表示でき、ボタンまたはEscで戻れます。表示の切替で録音や翻訳は停止しません。対応していない場合はウィンドウ内で画面を広げます。全画面では保存・詳細操作を「保存とその他の操作」から開けます。原文と訳文が対になり、新しい会話が一番上に表示されます。狭い画面では原文の下に訳文を表示します。

- 原文は受信に合わせて、訳文は話のまとまりと実際の生成に合わせて更新します。仮訳は続きによって変わります。
- 下へスクロールして過去の会話を読んでいる間は、その行の表示位置を保ちます。新しい会話が来たら件数を表示し、「最新へ戻る」で先頭へ戻れます。
- 「マイクと翻訳の設定」からマイク、訳すタイミング（早め・標準・文脈を優先）、日本語の補正を変更できます。開始前に設定してください。「文字サイズ」から文字を大きくできます。
- 「翻訳を終了」でマイクを解放し、残りの翻訳を続けます。残処理の間は再開や画面切替はできません。必要なら「残りの翻訳を中断」できます。未完了の原文・途中の訳文は残り、停止後に再試行できます。
- 停止後に会話をコピー・Markdown保存できます。出力は古い発話からの時系列順です。再開は同じ会話に追記します。「会話を空にする」は別操作です。
- 「詳細画面を開く」で、同じ会話の補正前後・モデル情報を確認できます。ライブ画面と詳細画面は一つの録音・翻訳・保存処理を共有します。旧版の保存済み会話も引き継ぎます。

起動済みの旧版から更新した場合は、起動ターミナルで終了して再起動し、ブラウザを再読み込みしてください。

## リアルタイム翻訳

[翻訳画面](http://127.0.0.1:3210/?view=translate#translate)で日本語→英語、英語→日本語を切り替えます。方向、文の区切り方、補正ON/OFFは録音開始前に選びます。モデルは文末判定・補正・翻訳ともLLM接続設定の共通モデルです。

| 区切りモード | ASR確定原文を受け取ってからの時間上限 | 文字数上限 |
|---|---:|---:|
| 速度重視 | 6秒 | 100字 |
| バランス重視（初期値） | 10秒 | 150字 |
| 文脈重視 | 15秒 | 200字 |

- ASRの**確定原文**に「。」が出たら、そこで区間を確定します。認識中の未確定文字はASRの確定を待ちます。
- 句点がなくても、文末・接続表現、約750msの間、約2秒ごとの判定で完結を検討します。LLMには原文中の境界候補を選ばせ、位置をサーバーで検証します。「ルールのみ」も選べます。
- 上限の時計は発話中も進みます。完結しなくても、節・読点・単語の境界を優先して分けます。句点は追加しません。区切り理由を表示・保存します。
- 約6秒後の仮訳は補正せず原文から生成し、後続に合わせて更新します。確定した区間は日本語補正後に翻訳します。処理待ちが1秒を超えた区間の補正は省略し、原文翻訳を優先します。
- 補正・文末判定・翻訳は一つの待ち行列で順次実行します。文の確定と翻訳の表示完了は別で、ASR確定待ち・処理待ち・生成時間が加わります。
- 停止後も残処理を続けます。「翻訳だけ中断」では文字起こしを続けます。各文は停止後に補正して再翻訳、または原文で再翻訳できます。
- 画面には認識原文、補正後、差分、翻訳に実際に渡した入力を区別して表示します。補正OFFでも、翻訳モデル自身が文脈を解釈するため、誤変換の字面どおりに訳すとは限りません。

各区間は1,200 UTF-8バイト以内、待機は最大32件です。翻訳待ちが溢れた文は原文を保持して再試行対象にします。補正推論の打切りは合計3秒、各文の翻訳は最大60秒、停止後の待機は最大10分です。翻訳の参考文脈には直前の確定訳を最大2件、補正には直前の認識原文を最大2件渡します。

旧データの途中の処理は中断状態で復元します。再試行には現在の共通モデルを使い、元のモデル名も記録します。旧ブラウザのモデル選択設定と `TRANSLATION_MODEL` / `BOUNDARY_MODEL` は通常利用に適用しません。接続先に障害がある場合も別の接続先やモデルへ自動で切り替えません。

## Whisperとの品質比較

[比較画面](http://127.0.0.1:3210/?view=compare#compare)では、同じ録音または2分以内のファイルを16kHzモノラルPCMに統一し、NemotronとWhisper large-v3へ順番に渡します。通常録音では先頭2分を比較用に保持します。翻訳モードでは音声を比較用に蓄積しません。

比較はLLM補正前のASR結果を使用します。正解文を入力すると文字誤り率（CER）を計算します。NFKC、大小文字、句読点・空白を正規化しますが、漢字とかな・漢数字と数字は同一視しません。正解文がなければ優劣を判定しません。

Nemotronは読み込み済みのサービス、Whisperは比較ごとにモデルを起動します。所要時間にはこの条件差があり、録音中の表示遅延を直接比較する値ではありません。WhisperのCPU併用など実際の実行環境を結果に残します。比較結果はJSONで保存してください。

Ollama接続時の翻訳画面の明示的な「翻訳モデルを比較」では、導入済みの専用モデルも比較できます。通常の翻訳には影響しません。専用モデルの導入は任意の `npm run setup:translation` です。

## 新しい環境でのセットアップ

Windows x64、Node.js 22.18以上、AudioWorklet対応ブラウザを使用します。Spark接続の端末は[Spark配備手順](deploy/spark/README.md)に従い、`npm ci`・`npm run build`と接続設定だけで利用できます。以下はこのPCでASR・Ollamaも動かす場合の手順で、CUDA対応NVIDIA GPUとドライバーが必要です。

```powershell
npm install
npm run setup:asr
# 品質比較を使う場合のみ
npm run setup:whisper
# 起動済みOllamaへGemmaを取得・更新
npm run setup:llm
npm run build
npm start
```

`setup:asr` はNeMo-Speech.cppとNemotronモデルを、`setup:whisper` はwhisper.cppとlarge-v3を取得します。各スクリプトでSHA-256を検証します。システムPATHは変更しません。`setup:llm` はOllama接続専用です。保存済み設定を含めた有効なOllamaへモデル取得を要求するため、先にOllamaを起動してください。OpenAI互換接続を選んだ状態ではモデル取得を行いません。録音・処理中はモデルを更新しないでください。

モデルの利用条件は [Nemotron](https://huggingface.co/nvidia/nemotron-3.5-asr-streaming-0.6b)、[Gemma](https://ollama.com/library/gemma4)、[Whisper](https://huggingface.co/openai/whisper-large-v3)を参照してください。kuromojiと標準辞書のライセンスは [第三者ライセンス一覧](THIRD-PARTY-NOTICES.md) にあります。

## 設定と構成

必要な場合だけ `.env.example` を `.env` にコピーします。

| 環境変数 | 既定値・用途 |
|---|---|
| `PORT` | `3210` |
| `ASR_URL` | `http://127.0.0.1:8081` |
| `OLLAMA_URL` | 保存設定・新LLM設定がない場合のOllama URL。未指定は `OLLAMA_HOST`、なければ `http://127.0.0.1:11434` |
| `OLLAMA_MODEL` | 従来方式の初期モデル。既定は `gemma4:latest` |
| `LLM_PROVIDER` / `LLM_BASE_URL` / `LLM_MODEL` | 新方式の初期設定。三つを一組で指定。保存済み設定を優先 |
| `LLM_API_KEY` | 新方式の初期APIキー（任意） |
| `LLM_DISABLE_THINKING` | OpenAI互換の対応モデルで明示的にThinkingを無効化する場合`true` |
| `SPEECH_MODE` / `SPEECH_URL` / `SPARK_GATEWAY_URL` | `local`または`spark`、音声API起点、Spark共通起点。保存済み音声設定を優先 |
| `SPEECH_API_KEY` / `SPEAKER_DIARIZATION` | 音声APIの初期キー、話者分離ONの場合`true` |
| `AUDIO_INPUT_PROFILE` | `browser`（既定）または`conference` |
| `NEMO_SPEECH_BIN` / `ASR_MODEL` / `ASR_DEVICE` | 独自ASR実行ファイル・モデル・デバイス |
| `WHISPER_BIN` / `WHISPER_MODEL` / `WHISPER_MODEL_LABEL` / `WHISPER_DEVICE` | 独自Whisper実行環境 |

保存設定がない場合、このPCは既存の `OLLAMA_HOST` により11435番へ接続します。Ollamaのシステム設定は変更しません。Ollamaの通常設定は `num_ctx=4096`、`think=false`、温度0、保持10分です。外部接続ではOllama固有の項目を送らず、コンテキストやGPU配置は接続先の管理に従います。

ブラウザのマイク → AudioWorklet → PCM16 → Node.js WebSocket → Nemotronという経路で認識します。Node.js内で文をまとめ、設定したLLMによる補正・翻訳へ進みます。整形・要約もバックエンド経由で、ブラウザからLLMサーバーへ直接要求しません。同時に一つの録音・処理セッションに制限し、停止後の残処理も排他します。

開発画面は別ターミナルで `npm run dev`。フロント変更後の本番利用には `npm run build`、バックエンド変更後には `npm start` の再起動が必要です。

## 保存と制限

- 音声認識は既存のNemotron接続先で行います。文章処理は設定したLLMのHTTP APIを使い、外部サーバーを選んだ場合は原文と必要な文脈をその接続先へ送ります。依存物とモデルの取得にはネット接続が必要です。
- 原文、補正、差分、結果、表示中の履歴はブラウザのlocalStorageに保存します。加えて会議ジャーナルは端末の`.local/sessions/`に保存します。サイトデータの削除では端末側ジャーナルは消えません。音声は保存しません。バックアップ・削除は利用者が保存ディレクトリで管理します。
- 比較の音声はメモリに一時保持し、Whisper比較時だけ `.runtime/compare-jobs/` に作業用ファイルを作ります。通常終了・中断時に削除しますが、強制終了時には残る場合があります。
- 手入力は24,000文字まで、整形・要約・録音後の補正APIは10,000 UTF-8バイトまでです。長文は1,200バイト以内に分割して処理します。要約は区間別の要約を連結し、文書全体を再要約する処理は行いません。画面に分割処理を通知します。
- 同音語の補正はASRの全誤りを直す機能ではありません。音の脱落、言い直し、専門用語、未知語の修復は対象外です。重要な内容は原文・差分を確認してください。
- 端末Webは127.0.0.1で待ち受けます。Sparkゲートウェイはキー認証と利用権を必須にし、LAN接続時はTLSまたはSSHトンネルを使用します。端末のWeb画面を別PC・スマートフォンへ公開する構成は扱いません。

`test:correction` は人工の日本語200例を設定したLLMへ渡し、補正率、不要な変更、処理時間、モデルdigestを `reports/correction-evaluation.json` に残します。この集合は実装調整にも使用しており、前置きだけ変えた関連例も含む回帰試験です。未知の会話に対する性能評価ではありません。

`test:gemma` は「選択→洗濯」、正しい選択の維持、補正OFF、日英両方向の翻訳、句点のない日英文の境界判定を確認し、`reports/gemma-smoke.json` に記録します。

`test:gemma-readiness` はNemotron起動中のモデル情報・配置・準備時間・JSON応答を、`test:caption-latency` は句点の有無×区切り3モード×補正ON/OFFの12条件を記録します。後者はASR確定テキストを模した入力による検証で、マイクやASR自体の遅延を含みません。

`test:long` は合成音声PCMをマイク相当の速度で15分送り、原文保持、処理完了、メモリを `reports/long-session.json` に記録します。テスト音声がなければ次で生成します。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\create-test-audio.ps1
$env:KOTOBA_LIVE='1'
$env:KOTOBA_TRANSLATION_LIVE='1'
npm run test:browser
```

ライブ翻訳の位置保持・継続利用試験は、180区間（5秒間隔の15分相当）を加速投入するUI試験です。`test:long` の実時間での音声入力試験とは別です。`KOTOBA_TRANSLATION_LIVE=1` では日英両方向のライブ画面と既存詳細画面で、実サービスに接続する仮想マイク試験も行います。検証サーバーを別ポートで動かす場合は `KOTOBA_TEST_URL` で指定できます。

ブラウザ試験はEdgeで合成音声の仮想マイクを使います。利用者の実マイクは操作しません。実マイクでのCER、騒音・発話者差、未使用の評価集合による補正品質は未評価です。実装時の具体的な結果と設計上の変更は、方針書の実装結果欄に記録します。
